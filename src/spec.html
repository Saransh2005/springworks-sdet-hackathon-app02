Address Verification Form

1. What this app is

A Digital Address Verification (DAV) intake tool. A candidate submits their current and permanent address; the server stores the submission and computes a naive "match %" between the two addresses.

2. API reference / spec

Base URL: https://sv-qa-02-address-verify.onrender.com

Address shape

Both current and permanent addresses share this shape:

{ "line1": "12 MG Road", "city": "Bengaluru", "state": "Karnataka", "pincode": "560001" }
  • line1, city, state are required, non-blank strings (surrounding

whitespace should be trimmed before storage/comparison).

  • state must be one of the fixed list of states offered in the UI dropdown

(Karnataka, Maharashtra, Delhi, Tamil Nadu, Telangana, Uttar Pradesh, West Bengal, Gujarat).

  • pincode must be exactly 6 digits, not starting with 0 (matches

/^[1-9][0-9]{5}$/). Anything else is invalid.

POST /api/address

Body:

{
  "candidateId": 101,
  "current": { "line1": "...", "city": "...", "state": "...", "pincode": "..." },
  "permanent": { "line1": "...", "city": "...", "state": "...", "pincode": "..." },
  "sameAsPermanent": false
}
  • sameAsPermanent defaults to false if omitted.
  • If sameAsPermanent is true, the server stores the permanent address as

an exact copy of the current address — the submitted permanent object (if any) is ignored.

  • current is always validated. permanent is validated the same way,

unless sameAsPermanent is true (in which case it's derived from current, so it doesn't need to be separately valid).

  • Any validation failure returns 400 with an error message and stores

nothing.

  • On success, computes matchPercent: the percentage of the 4 address

fields (line1, city, state, pincode) that match between current and permanent, compared case-insensitively. Two identical addresses score 100; completely different addresses score 0. Returns 201 with the stored submission:

{
  "id": 1,
  "candidateId": 101,
  "current": { ... },
  "permanent": { ... },
  "sameAsPermanent": false,
  "matchPercent": 100,
  "createdAt": "2026-07-01T09:00:00.000Z"
}

GET /api/address/:candidateId

Returns the submission for that candidate.

  • 200 with the submission object if found.
  • 404 if no submission exists for that candidate id.

GET /api/address

Returns 200 with a JSON array of all submissions.

3. UI spec

  • Submit Address form: Candidate ID, Current Address (line 1, city,

state dropdown, pincode), a "Permanent address is the same as current" checkbox, and a Permanent Address section.

  • The state dropdowns require an explicit choice — no state should be

pre-selected by default.

  • Typing an invalid pincode shows an inline error message before the form

is submitted.

  • Checking "same as current" disables the Permanent Address inputs and

keeps them mirroring the Current Address fields for as long as the checkbox stays checked — including if the candidate keeps editing the Current Address afterward.

  • On submit: a success message is shown only when the submission actually

succeeds; a failed submission shows an error message instead, and the submitted-addresses list only gains a new row on success.

  • Submitted Addresses table: shows candidate id, current address,

permanent address, whether "same as permanent" was set, the match percentage (shown with a % sign), and the submission timestamp.
